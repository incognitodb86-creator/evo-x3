## Verdict: NOT READY

The build-and-test idea is sound. So are the hard stops already in U3: Windows NVMe physically unplugged, stop if the slot can't be reached, own ESP, `update_nvram=false`. Four problems block it, though:

- **R5 promises things the plan can't deliver as written.** It says only the X3 can reach ComfyUI, but the tailnet still allows everything. It says Tailscale Serve will check a key, but Serve can't. And the submit checks run only on the caller's side.
- **B5 key handling breaks the "one locked file on AlienPc" rule.** The plan never says how keys get from the Windows `.env` onto a Linux disk that must never mount C:.
- **The disk-match design has one untested and invalid line.** B2 swaps it out for the VM test, and B4 removes the installer's safety prompt.

**What can start now:** B1 repo skeleton (no secrets, no credentials) and the B2 VM test with throwaway test credentials only. B3 and B4, X2 and later, and any key or QNAP/Gitea credential work wait for the blockers below.

## ACL decision card (as the plan should carry it, not written yet)

The plan has no card text, only "The ACL change is a Derrick yes card" (plan:L75). Checked against what Derrick asked for:

- **Precise rule?** No. The plan says "the X3 node (or the Render caller's tag)", with no destination tag or port. It needs to name: the source (`tag:x3` or the X3 node), the destination (the Linux node's tag, for example `tag:alienpc-render`), and the port (the Serve port that fronts the proxy, for example `:443` or a named port).
- **Breaks other callers?** Not assessed in the plan. Removing the allow-all rule (needed, BL1) affects **every** tailnet flow, not only ComfyUI. That includes Derrick's phone and browser to Open WebUI and pi-mobile on the X3, the box (`tag:box`) to Gitea and the X3, AlienPc Windows to the QNAP (Kopia, ntfy), Household tools, and Max's SSH to both PCs. If Derrick wants to open the ComfyUI UI from his phone or browser, his user needs a grant too.
- **Rollback?** None stated. Before any edit, save the current policy (in Tailscale's admin history, or as an offline copy kept outside the brain, since the policy contains user emails). Add a policy `tests` block that asserts the flows above still work, so a bad edit is rejected on save.
- **Closes or keeps allow-all?** Not stated. Only closing it delivers R5's "only the allowed caller".
- **Each option's tradeoff?** Not written. Suggested options:
  - **A. Keep allow-all for now. ComfyUI is protected by the keyed proxy and route allowlist (BL2), plus the server-side template check (BL3).** Gives up: no network-level limit. Any tailnet device, including a compromised one, can reach the proxy and try keys. The X3 audit's open-ACL finding stays open. Nothing else breaks, and no extra testing is needed.
  - **B. Replace allow-all with explicit grants:** X3 → ComfyUI port only, plus every current flow listed and tested with ACL `tests`. Gives up: about an hour of inventory and testing, and the risk of breaking the phone, Kopia, Gitea, the box or Household tools if a flow is missed. Closes the X3 audit ACL finding and makes R5's pass test literally true.
  - (Reviewer lean, not a pick: A now, so R5 isn't blocked; B as its own job with the flow inventory.)
