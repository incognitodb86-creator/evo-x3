# EVO-X3 USB backup job (Hydrogen Low, run 2). Derrick approved, Nov 14 2026 9:15 PM CT: "Wipe the drive first", then back up Windows to the new 500 GB drive.
A separate Orchestrator run is working in C:\evo-x3 at the same time. Don't touch its files or runs\orch_full_20261114. Write only under runs\h2_usb_backup_20261114 and records\usb-backup.md.

1. Identify the target. It must be the disk with BusType USB, FriendlyName "ASMT 2115", about 447 GB, IsBoot False and IsSystem False (currently disk number 1). Look it up by those properties, not by number alone. If no disk matches exactly, or more than one does, STOP and report. NEVER touch disk 0 (the CT2000E100SSD8 NVMe, which is the X3's Windows drive).
2. Wipe it. Clear-Disk -RemoveData -RemoveOEM, Initialize-Disk GPT, one partition at maximum size, NTFS, label X3BACKUP, drive letter F if it's free (otherwise any free letter). This shell is not elevated, so write a .ps1 in the run folder and launch it with Start-Process powershell -Verb RunAs -Wait. Derrick clicks Yes on the UAC prompt on the X3's screen. If UAC is cancelled, retry at most twice, waiting about 2 minutes each time, then STOP with BLOCKED.
3. Back up. Use the built-in Windows system image: wbadmin start backup -backupTarget:<letter>: -include:C: -allCritical -quiet, run elevated the same way and logged to a file in the run folder. Check C: BitLocker status read-only with manage-bde -status C:, and record only the protection on/off and percentage. NEVER print, copy or store a recovery key or password, and don't change BitLocker.
4. Verify it. Run wbadmin get versions -backupTarget:<letter>:, and check that <letter>:\WindowsImageBackup exists, with its size.
5. Write C:\evo-x3\records\usb-backup.md: the disk identity, before and after, the commands run, the backup version id and time, the size, and PASS or FAIL. Put the same summary in runs\h2_usb_backup_20261114\RESULT.md.
No partition, BIOS or boot changes on disk 0. No downloads. No spending.
