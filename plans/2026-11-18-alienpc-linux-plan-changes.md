## 1. Changes

| ID | Change | Why |
|---|---|---|
| LX1 | **Decided (Derrick, 2026-11-18): render + Swift lane.** Under Linux the AlienPC also runs native Strata Swift (`coding_swift15_iq3s_esp`), with `comfyui_auto`, `comfyui_longvideo` and Swift in one exclusive llama-swap group. The waiting gate stays on `:8085` and the fail-fast gate (`:8086`, `--fail-if-busy`) is behind Tailscale Serve `:8447`, as in the main plan's P5.1. Replace rev 4's "ComfyUI-only", R5's "no local LLM runs on AlienPc Linux" and X4's "AlienPc never loads a local LLM". U8 builds native Strata, not Forge. U10 records Swift's tok/s as information only, not pass/fail. | Main plan D8 and Phase 5 (Nov 18) came after rev 4 (Nov 16). |
| LX2 | **Access rules = the main plan's P2.4:** a narrow form of the review's D1 option B. It keeps today's other flows and limits only the ports with no login (`8443-8447`). Give the Windows and Linux AlienPC nodes the same tag, so the rules cover whichever OS is up. The review's FX3 already names a separate Linux node (`alienpc-linux`). | Review BL1, FX3. |
| LX3 | **Same Manager setting:** the Linux build starts with ComfyUI-Manager at `strong`, or without Manager (the follow-up plan's S1). | Review BL2(c). |
| LX4 | **Benchmark against tuned Windows.** U10 runs after the follow-up plan's render-speed tests (its "Faster H3 Max beta7 renders" section, R1-R7), so Linux is compared with Windows at its best. It uses the same protocol on both: warm-up, at least 3 runs, median, same seed, hash-matched models. The Windows baseline is the real render time (about 142 s for a 124-frame B2 clip on Oct 30), not the old runner's poll-rounded 180 s. If those tests adopt the `activation_learned_HQ` checkpoint, stage it on Linux too. | Comparing with untuned Windows would credit Linux with gains Windows can also get. |
| LX5 | **Headless boot as a U10 row:** measure the clip once with a desktop session and once from `multi-user.target`. U9 (Grok Bot local execution) needs a desktop session, so headless becomes the default only if U10 shows it matters and Grok Bot can run without one. | The extra VRAM a headless boot frees isn't measured on this box. |
| LX6 | **Claims not to plan on.** A Nov 18 Gemini review's Linux gains (22-53%, its per-stage table, "1.6x on your hardware", sol-attn numbers) have no sources, and its 180 s baseline was the poll-rounded runner time. The Linux plan's own estimate (about 5-15%) stands until U10 measures it. | Unverified. |
| LX7 | **Linux ComfyUI tuning, run as extra U10 rows** after the plain Linux row (same graph, seed and models; warm-up, at least 3 runs, median; one change per row):<br>1. **Pinned memory on:** drop `--disable-pinned-memory`. That flag exists only because of Windows WinError 1450 errors.<br>2. **Fast-disk both ways:** ComfyUI auto-detects a fast NVMe on Linux by link speed (`comfy/storage.py`), so the 9100 PRO will likely show `fast_disk=True`. Read the log line, then test `--disable-fast-disk` against the default.<br>3. **Cold vs warm:** time the first render after boot apart from repeat renders, because Linux keeps recently read model files in RAM.<br>4. **Headless:** LX5.<br>Each of these changes only where weights or memory sit, so frames should match on the same seed. Still left out on Linux: sol-attn and SageAttention (both change the output) and `torch.compile` (conflicts with Dynamic VRAM). | The follow-up plan's Windows render-speed steps (R1-R7) carry over except R4, the Windows driver setting. These rows are the Linux-only part. |
| LX8 | **Two review items the follow-up plan decides for both OSes:**<br>1. **D3 (secondary LLM nodes on the AlienPC)** is the follow-up plan's W3. If the `API Universal Writer` node stays, the Linux build needs the pack's Linux key storage (`MINIMAX_H3_VAULT_KEY`, kept stable across restarts, with a separate backup), `MINIMAX_H3_API_ADMIN_TOKEN`, and FX6's leak test. If it goes, AlienPC Linux holds no LLM key.<br>2. **BL3 (server-side template check)** is the follow-up plan's S2. Build the same allowlist on both OSes, with graphs that contain an LLM node left off it. | One answer for both OSes. Without a vault key the pack disables key entry on Linux. |
| LX9 | **2x upscale on Linux.** The Windows runner (`run_queue.py`) upscales every finished clip 2x by default with NVIDIA's `nvvfx` library, from a Windows venv. The Linux plan doesn't mention it. In U8, check that `nvvfx` installs and runs on the Linux build. If it doesn't, Linux clips stay at 768x1344 (the same split as the follow-up plan's G5), and U10 must say so. | A missing post-pass would make Linux clips smaller than Windows clips without anyone noticing. U10 times the render, not the upscale. |
