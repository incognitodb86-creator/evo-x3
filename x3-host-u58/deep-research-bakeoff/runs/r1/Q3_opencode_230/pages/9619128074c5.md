# OpenCode 2.3.0 — subagents run in the background by default
In short
OpenCode 2.3.0 runs subagents in the background by default, so several can work at once while you stay in the parent session. The TUI groups tool calls into a collapsible row, and the desktop app can jump to earlier prompts.
Anomaly · 2026-11-13 · 1 source checked
OpenCode 2.3.0 makes subagents non-blocking and trims the transcript down to a quiet activity row.
## What is it?
Background subagents are now the default in OpenCode 2.3.0: a subagent call returns at once, runs on its own and reports back when it is idle, so a user can start several in parallel without leaving the parent session. The open-source coding agent also ships quieter transcripts and a "Jump to message" command in the desktop app.
## How does it work?
The TUI now defaults to low verbosity and folds tool calls and thoughts into one collapsible activity row; medium or high verbosity brings back every step. Experimental flags add MCP events (`mcp_events`) and move timed-out shell commands to the background (`shell_timeout_background`), and client certificates for mutual TLS are set through `settings.tls`.
## Why does it matter?
Long agent sessions get easier to follow and to parallelise. Plugin and SDK authors gain MCP event subscriptions, cooperative cancellation through `ToolContext.signal`, and an experimental `session.fork` hook, while shell commands now survive server handoffs.
## Who is it for?
developers using or extending OpenCode
## Try it
Desktop: Cmd/Ctrl+Alt+G opens Jump to message
