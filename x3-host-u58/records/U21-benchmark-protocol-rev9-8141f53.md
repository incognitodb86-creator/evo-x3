### U21. Benchmark protocol (rev 9, R17, t341u/t343u; Max Architect 3; runs pending Derrick's yes)
**Status:** folded in at Derrick's ask (t343u). He has **not** yet said yes to running it. Nothing here changes a default (Q3, Q4, Q8, Q10, the writing-model engine, or llama-swap groups). RELAYED (Max, Nov 15): the X3 is already serving with an exclusive llama-swap `main` group (`gemma4-heretic`, `flash-next`, `qwen27b`, embed) in `/etc/evo-x3/llama-swap.yaml`; Max measures tg tok/s, swap time (~22 s Heretic, ~60 s Halogen), KV/GTT use, max context, refusal probes, Prompt maker's blind writer scoring (fixed seeds, 3 runs) and render OBJECTIVE ok/fail + queue-to-final; there is no pp/TTFT/depth sweep, no fixed prompt set, no single harness, and results are scattered (`~/evo-x3/records/`, partly stale `RESULTS.md`).

Community way: llama-bench README (live master, accessed 2026-11-15) + eugr/llama-benchy README ("as of 2026-01-02") + kyuz0 toolboxes benchmark method (@765cc5c7, now marked legacy) + HALOBENCH benchmark protocol (2026-08-04, ladder 2026-08-17) + EQ-Bench CW v3 README + Comfy-Org/comfyui-benchmark README → **adapt**: use both harnesses as-is, a short depth ladder, mean ± sd with overlap = tie, a quiet window and a coherence gate; build nothing new except one prompt file and one record template. Detail, quotes and the audit checklist: [research/2026-11-15-llm-benchmarking-methods.md](../research/2026-11-15-llm-benchmarking-methods.md).

- **B1 Quiet bench window (gate; Max Architect 3).** Only when Derrick says Render/Sydney are idle (or a render chain has finished writing). Pause llama-swap or load only the bench model; nothing else resident, no crons; note page-cache state. Record power mode (default stays Balanced 85 W), IOMMU state, kernel, engine and toolbox digest/commit, and temperature if readable (else NO_DATA). Strix Halo GPU memory is GTT from shared RAM, so another resident model or a power-mode change moves the numbers (HALOBENCH: a decode collapse traced to memory pressure). **Pass:** the llama-swap log shows no non-bench requests during the window, and the header fields are filled.
- **B2 Free default speed suite (gate; Max Architect 3).**
  - Engine: `llama-bench -o json` per (model, backend, build) with pp512 and tg128 at depths **d0 / d32768 / d131072** (d262144 for Flash-Next only if it fits), `-r 5` at d0 and d32768, `-r 2` deeper (HALOBENCH found deep rows barely move and uses N=1 above 32K; this saves hours). Record `-fa` (on/off/auto in current builds), `-ctk/-ctv`, `-b/-ub`. llama-bench is the **floor**: it does not run MTP/speculation, so Flash-Next's MTP number comes from the served path. If an engine (Halogen; Gufo UNVERIFIED) has no llama-bench, it gets served-path rows only.
  - Served: `llama-benchy` against llama-swap with the same depths, `--runs 3`, `--no-cache` (the README warns that cached prompts give falsely low TTFT and high pp), reporting TTFR, est_ppt and e2e_ttft.
  - Keep the existing items unchanged: the U12 cold TTFT fixture (no warmup, first request after load) and the U6 27B DFlash2 with/without long-context pair.
  - Report mean ± sd. Call a result a **tie** when the ranges overlap (kyuz0 rule). One variable at a time, as U19 already says.
  - **Pass:** a JSON file per engine run plus a llama-benchy table exist for every loaded slot that is tested, every row has mean ± sd, and every comparison says win or tie by the overlap rule.
- **B3 One results file per run, with provenance (gate; Max Architect 3).** Raw JSON stays on the X3 at `~/evo-x3/bench/<YYYY-MM-DD>-<run-id>/` (the brain is markdown only). The one stated home for results is `40_projects/compute-expansion/records/bench/<YYYY-MM-DD>-<run-id>.md`: engine commit (llama-bench `build_commit`), backend, full flags, model filename **and sha256** (llama-bench JSON has no hash), kernel, power mode, IOMMU, window start/end CT, the raw JSON path and its sha256. **Coherence check first:** one real generation per (model, backend, build), checked for sense; if it fails, its throughput rows are deleted, not footnoted (HALOBENCH). **Pass:** the record has every provenance field and a coherence line per (model, backend, build); `RESULTS.md` links it and stale Gufo/Halogen labels are fixed or marked.
- **B4 Writer quality (gate; Prompt maker scores, Max Architect 3 runs).** Keep Prompt maker's blind A/B, 3 runs per ask and fixed seeds. Add a **pinned prompt file** (about 8–12 prompts, saved with its git hash; no secrets, no Imagine prompts) and pinned samplers written in the record. Swap A/B order between rounds (EQ-Bench runs A/B and B/A). Temperature 0 plus a seed does **not** replay exactly on Vulkan (HALOBENCH: three different outputs), so the 3 runs are samples, not replays. **Pass:** the record names the prompt-file hash, the samplers and the seeds; scores are per arm on blind labels with order swapped.
- **B5 Small long-context check (gate; Max Architect 3).** A free RULER subset (or a needle subset) at two or three lengths (for example 32K and 128K) for Flash-Next and the 27B, recording tokenizer, length and seed. Needle-only results are an upper bound: RULER found most models ace plain needle tests but degrade on harder tasks as length grows. **Pass:** accuracy per length per model in the record, with tokenizer, length and seed.
- **B6 Video on AlienPc (gate; Max Architect 3, only under the AlienPc lease, never during a render).** On one pinned ComfyUI H3 workflow and seed (the current single-pass beta7_int8HQ, 768x1344, RELAYED), log s/it per step and peak VRAM (for example with Comfy-Org/comfyui-benchmark, which reads nvidia-smi — fine on the RTX 5070 Ti; installing it needs its own OK) next to OBJECTIVE ok/fail and queue-to-final time. **Pass:** one record row per benchmarked clip with s/it, peak VRAM, ok/fail and queue-to-final.
- **Optional, NOT defaults — each needs Derrick's own yes:** (1) the EQ-Bench Creative Writing v3 paid judge (Claude Sonnet 4.6, about $10 per model per the README; its README lists NSFW aversion as an uncontrolled judge bias, which matters for Heretic); (2) Max's coding and deep-research bake-off (Harbor + Docker; Terminal-Bench, SWE-bench Verified subset, Aider polyglot, Forge tasks), which needs installs, downloads, a key and overnight slot time. The research note lists fixes it needs first: more Forge trials than the 10-point rule can resolve, public-benchmark contamination labels, pinned harness/dataset versions, and blind human scores.
- **Size:** the default suite is small and free: about 3 models × 3 depths on one backend each, plus one served pass, one writer round and one long-context subset. Wider sweeps (every backend, every KV type) only when a unit (U6, U19, U20) asks for that comparison.
- **Risks and limits:** benchmarks inside the exclusive `main` group stall live Render/Sydney chats (hence B1); Vulkan output is not deterministic; GTT/unified memory and power mode or heat shift results, so the header records them and a re-run is needed after any change; prompt caching hides prefill cost unless `--no-cache` is set (the cold TTFT fixture stays cold on purpose); llama-bench numbers are floors for MTP models.
